#1 · BUG-005High

Order History shows empty orders that can still be repeated

Page: Order History

Steps

  1. Sign in with an account that has placed orders before.
  2. Open Order History from the menu.
  3. Look down the list of orders.
  4. On a row with no cardholder name, click View, then try Repeat Order. Do not finish the repeat order.

Expected

Every row shows a cardholder, an item and a quantity. Empty orders are not listed.

Actual

Some rows have no cardholder or item, quantity 0, status Processing. View and Repeat Order still work on them.

#2 · BUG-006High

Bilingual card turns into an English card after a page refresh

Page: Customize

Steps

  1. Go to the Catalogue and open Business Card Bilingual.
  2. Click Customize. Check that the form has a French title field.
  3. Refresh the page (Cmd+R on Mac, F5 on Windows).
  4. Also try: copy the page address, open a new tab, and paste it there.

Expected

The page still shows the Bilingual form with the French title field.

Actual

The form shows as English, with no French title field. Sometimes the page fails with a time-out error (408).

#3 · NEWHighNeeds confirming

Editing a Bilingual card from Shipping turns it into an English card

Pages: Shipping → Customize → Cart

Steps

  1. From the Catalogue, customize a Business Card Bilingual. Fill in a name and a French title, preview the proof, approve it and add it to the cart.
  2. Go back to the Catalogue and add a Business Card English to the cart the same way.
  3. Go to Shipping and click Edit on the Bilingual card.
  4. Look at the form. Save the card again and check the cart.

Expected

The Bilingual form opens with its French title. After saving, the cart still says Bilingual.

Actual (from the code)

The form opens as English with no French title. After saving, the card is listed as English, so the order changes.

Found by reading the code, not tested in the browser yet. Same cause as bug #2.

#4 · BUG-001Medium

Footer links do nothing

Every page, bottom

Steps

  1. Scroll to the bottom of any page.
  2. Click Contact Us, then Security / Privacy Policy, then Terms of Use / Copyright.
  3. Switch the site to French and click the same three links again.

Expected

Each link opens its page.

Actual

Nothing happens when you click.

#5 · BUG-002Medium

Screen reader reads code instead of "Address Book"

Page: Address Book (the My Address Book / Office Addresses tabs)

Steps (Mac)

  1. Open Address Book.
  2. Turn on VoiceOver with Cmd+F5.
  3. Press Tab until you reach the My Address Book tab, and listen.
  4. Turn VoiceOver off with Cmd+F5.

Expected

VoiceOver says "Address Book, navigation".

Actual

VoiceOver reads raw code: {{ BF.i18n('label_general_addressBook') }}.

The page looks normal. Only screen-reader users notice this.

#6 · BUG-003Medium

Admin: address count always shows 0

Page: Admin home

Steps

  1. Sign in as an admin and open the Admin page.
  2. Read the number on the Manage Addresses tile.
  3. Click the tile and count the offices in the list.

Expected

The tile shows the number of offices in the list (22 today).

Actual

The tile always says 0.

#7 · BUG-004Low

Admin: title and credential counts never change

Pages: Admin home, Manage Titles, Manage Credentials

Steps

  1. On the Admin page, write down the numbers on the Manage Titles tile (39) and the Manage Credentials tile (32).
  2. Open Manage Titles. Count the titles on the English tab plus the French tab.
  3. Add a test title named QA Test Title, then go back to the Admin page.
  4. Check the tile again, then delete QA Test Title.

Expected

The tile matches the English + French total and goes up by one after you add a title.

Actual

The tile always shows 39 for titles and 32 for credentials, whatever the lists contain.

The bot compared 39 with the English tab alone (32). The real problem is that the numbers are fixed and never update.
